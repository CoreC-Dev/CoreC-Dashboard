# 核心信念（智能体优先的操作原则）

> 这是**争议的裁决依据**。当"该不该这么做"出现分歧时，回到这份文件，而不是回到聊天记录。

## 通用原则
1. 人类掌舵，智能体执行。人类不直接贡献代码行。
2. 工程师的工作是设计环境、明确意图、构建反馈回路。
3. 上下文是稀缺资源；给地图，不给说明书。
4. 智能体在运行时看不到的东西，对它来说不存在。
5. 强制不变量，不微观管理实现。
6. 中央强制边界，本地允许自主表达。
7. 纠错成本低，等待成本高。
8. 技术债是高息贷款，小额高频偿还。
9. 遇到卡点先问："缺的是什么能力？如何让它既清晰可读又可强制执行？"
10. 人类品味要持续被捕捉——写进文档，或直接编码进工具。
11. 交互式决策必须落盘：确认过但不写进仓库的决策等于没做。
12. 改造存量项目时，重构不改变业务行为；行为变更必须显式登记并单独提交。

## 本项目专属信念
13. **feature-sliced 边界是第一道防线**：`features/*` 之间不直接互引。新增跨域需求先问"该共享逻辑是否应下沉到 `lib`/`api/hooks`/`stores`"，而非在 feature 间拉线。
14. **纯函数优先**：可纯化的逻辑放 `lib/`，不引 i18n/store 单例。UI 原语（`components/ui`）保持纯展示，不引 `hooks`/`stores`。
15. **边界必校验**：后端响应、导入 JSON、用户粘贴 YAML 均经 zod 或显式校验，不信任外部形状。
16. **服务端状态归 react-query，本地状态归 Zustand**：不把服务端数据复制进 Zustand 长期保存（`configStore` 例外：工作副本需可编辑/回退）。
17. **流式数据必须有界**：WebSocket 缓冲、图表窗口、死信列表、历史快照均封顶；无界增长即缺陷。
18. **密钥不落明文持久层**：API 密钥存 sessionStorage（非 localStorage），导出默认脱敏（见 `docs/SECURITY.md`）。
19. **行为守恒可证**：重构后用测试或对拍证明同输入同输出；行为变更单独提交并在台账标注"变更行为"。
